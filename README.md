# Noquelle — лендинг с предзаказом мерча

Статический сайт: один `index.html`, каталог в `catalog.json`, фото в `img/`.
Живёт на Netlify, обновляется прямо из админ-панели — файлы вручную заливать не нужно.

## Что где лежит

| Файл / папка          | Что это                                                             |
| --------------------- | ------------------------------------------------------------------- |
| `index.html`          | Вся вёрстка, стили и логика магазина + админ-панель                 |
| `catalog.json`        | Товары, акции, настройки магазина. **Это то, что меняет панель**     |
| `img/`                | Фото товаров: `<id>-<n>.webp` (до 1400px) и `<id>-<n>@480.webp` (превью для карточек) |
| `fonts/` + `fonts.css`| Comfortaa и Sofia Sans Condensed локально, без Google Fonts          |
| `netlify/functions/unlock.js`  | Проверка пароля панели (пароль только в переменных Netlify)   |
| `netlify/functions/publish.js` | Публикация: проверяет пароль и коммитит `catalog.json`        |
| `netlify/functions/stock.js`   | Счётчик проданного для «Осталось N шт» (Netlify Blobs)        |
| `netlify.toml`        | Настройки Netlify: что раздавать, редирект `/api/publish`, кеш       |

## Как редактировать товары

1. Открой сайт и добавь `#admin` в конец адреса: `https://<сайт>.netlify.app/#admin`
2. Введи пароль. Он проверяется на сервере (`/api/unlock`) и **в файлах сайта не лежит** —
   ни в `index.html`, ни в `catalog.json`. Меняется только в переменной `ADMIN_PASSWORD`
   на Netlify.
3. Меняй товары, смотри превью. Всё это время правки лежат черновиком в твоём браузере — их не видит никто.
4. Жми **«Опубликовать на сайте»**. Пароль второй раз не спросит — он запомнен с момента входа.
   Каталог уедет в GitHub, Netlify пересоберёт сайт за минуту-две.

Пароль для входа и для публикации — **один и тот же** (`ADMIN_PASSWORD`).
Поскольку теперь это единственная настоящая защита, пусть он будет нормальным,
а не `007`: функция входа искусственно притормаживает ответ, но длинный пароль надёжнее.

Кнопка «Скачать catalog.json (бэкап)» сохраняет копию на всякий случай.
«Загрузить каталог из файла» — восстановить из такого бэкапа.

## Настройка Netlify (делается один раз)

### 1. Подключить репозиторий
Netlify → Add new site → Import an existing project → GitHub → `kayokin25/noquelle-orders`.
Build command оставь пустым, publish directory — `.` (это уже прописано в `netlify.toml`).

### 2. Создать токен GitHub
1. https://github.com/settings/personal-access-tokens/new
2. **Repository access** → Only select repositories → `noquelle-orders`
3. **Permissions** → Repository permissions → **Contents** → *Read and write*
4. Сгенерируй и скопируй токен (показывается один раз).

### 3. Вписать переменные окружения
Netlify → Site configuration → Environment variables → Add a variable:

| Переменная        | Значение                                              |
| ----------------- | ----------------------------------------------------- |
| `ADMIN_PASSWORD`  | пароль входа в панель **и** публикации — придумай свой |
| `GITHUB_TOKEN`    | токен из шага 2                                       |
| `GITHUB_REPO`     | `kayokin25/noquelle-orders` *(необязательно)*          |
| `GITHUB_BRANCH`   | `main` *(необязательно)*                               |

После добавления переменных нажми **Deploys → Trigger deploy → Clear cache and deploy site**,
иначе функция их не увидит.

Ни токен, ни пароль в коде сайта не лежат и в браузер не попадают — только в переменных Netlify.
Если `ADMIN_PASSWORD` не задан, панель честно об этом скажет и не откроется.

## Как добавить новое фото товара

Через панель можно вставить ссылку или загрузить файл — загруженный файл попадёт
в `catalog.json` как base64. Это работает, но утяжеляет каталог (его грузит каждый посетитель).
Панель предупредит, если каталог перевалит за 300 КБ.

Правильный путь для новых фото — положить файлы в `img/` через git:

```bash
py compress-images.py путь/к/фото.png p_new-0
```

Скрипт положит `img/p_new-0.webp` и `img/p_new-0@480.webp`, а в панели останется
вписать в галерею товара `img/p_new-0.webp`. Превью подставится само.

## Остатки товара

У товара есть необязательное поле **«Осталось в наличии, шт»**:

* пусто — учёта нет, товар продаётся как обычно;
* число — на карточке появляется «Осталось N шт», и в корзину не положат больше;
* `0` — товар показывается как «распродано».

**Число уменьшается само с каждым заказом.** Правило одно: вписывай столько,
сколько физически лежит на полке. Вписала новое число — счётчик проданного
обнулился, отсчёт пошёл от него заново (это и есть «пополнила склад»).

В списке товаров в панели видно и то, и другое: «осталось 5 из 8» + «продано 3».

### Как это устроено

Счётчик живёт в Netlify Blobs и обслуживается функцией `netlify/functions/stock.js`:

* `GET /api/stock` — сайт читает проданное при загрузке (не блокируя отрисовку:
  каталог появляется сразу, цифры догоняют);
* `POST /api/stock` — сайт сообщает о заказе.

**Google Apps Script при этом не меняется вообще.** Запрос к счётчику идёт
отдельно от отправки заказа: если он не дойдёт (офлайн, функция упала), заказ всё
равно уедет продавцу как раньше — просто остаток не сдвинется, и его можно
поправить руками в панели.

Ограничения, о которых стоит знать:

* эндпоинт публичный, так что теоретически кто-то может накрутить счётчик;
  лечится тем, что ты просто заново вписываешь фактический остаток;
* два одновременных заказа в одну и ту же миллисекунду могут «съесть» один
  инкремент — при здешних объёмах это не встречается, лечится так же.

## Локальный просмотр

`catalog.json` подгружается через `fetch`, поэтому просто открыть `index.html`
двойным щелчком не получится — нужен локальный сервер:

```bash
npx serve .
```

## Приём заказов

Заказы уходят POST-запросом в Google Apps Script — адрес в `catalog.json` →
`shop.orderEndpoint`, меняется в настройках панели.
